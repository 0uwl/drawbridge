# Drawbridge v0.3.2: nginx Reverse Proxy for TLS

## Context

A plain HTTP request against Drawbridge's HTTPS port gets a hard
`Connection reset by peer`, with nothing logged and nothing catchable in
Flask/WSGI code — confirmed by running it locally. Gunicorn
(`drawbridge/gunicorn.conf.py`) binds one socket wrapped directly in TLS
(`certfile`/`keyfile` from `drawbridge/tls.py`'s self-signed cert), and a
client's plaintext bytes just fail the TLS handshake below the WSGI layer
entirely. A same-port redirect is architecturally impossible — there's no
way to speak plaintext HTTP back on a socket already committed to
negotiating TLS from byte one.

This introduces a 4th pod container, `drawbridge-nginx`, to do what
Gunicorn was never meant to: terminate TLS properly and give a plain-HTTP
request against the *same* port a clean, helpful response instead of a
handshake failure. A separate redirect port was considered and rejected —
the realistic failure mode is someone using `http://` against the port
they already know (`8080`), not a different port entirely, so a second
port nobody would ever type doesn't fix anything. Instead, nginx uses its
`stream` module with `ssl_preread` to inspect the first bytes of each
connection on `8080` *before* deciding where to route it: a genuine TLS
ClientHello goes to the real HTTPS server block; anything else
(`ssl_preread_protocol` comes back empty — plaintext HTTP always fails to
parse as one) is routed to a small static responder telling the client to
use `https://`. One externally-visible port, protocol-detected, instead of
two. Confirmed working end-to-end against a real built image: plain HTTP
gets the friendly message, a real TLS handshake reaches the app, and a
non-HTTP/non-TLS garbage connection just gets nginx's ordinary 400.

Along the way this also makes the previously dev-only `TLS_DISABLED`
escape hatch into a supported "bring your own reverse proxy" production
mode, since the mechanism (Gunicorn binds plain HTTP with no cert) is
already exactly what that use case needs.

**Frontend serving stays exactly as it is today** — nginx only proxies
(API + frontend) to Gunicorn; Gunicorn keeps building/serving the SPA
unchanged. Having nginx serve the frontend directly was considered and
deliberately deferred: it would require the frontend's build output to be
readable by two separate container images (a duplicated build stage or a
shared volume), for a static-asset-serving performance benefit that
doesn't matter at Drawbridge's admin-facing scale.

**`drawbridge-bootstrap` stays a separate container — deliberately not
folded into nginx.** Folding ZTP script serving into `drawbridge-nginx`
was considered (nginx could trivially serve a static file too) and
rejected: this pod is meant to be modular — an operator who doesn't want
device syslog collection just doesn't start `drawbridge-rsyslog`, and one
bringing their own reverse proxy just doesn't start `drawbridge-nginx`.
ZTP script serving is not in that category — it's core, non-optional
functionality devices cannot provision without. Bundling it into an
optional container would mean disabling the optional one silently breaks
a required one. `drawbridge-nginx` handles TLS termination only; the pod
grows to **four** containers, not three (`drawbridge-bootstrap` stays
exactly as v0.3.1 shipped it).

**Not optional polish — a required correctness fix:** once nginx proxies
to Gunicorn over loopback, every request's `request.remote_addr` becomes
nginx's own address unless corrected. `request.remote_addr` is the actual
security gate behind the whole ZTP session model: `drawbridge/api/leases.py`
pins a `ProvisioningSession` to the calling IP on `provision-request` and
checks it again on `provision-complete` (`session_mismatch`), and
`find_active_session_by_ip()` (used to gate image/config downloads) looks
up the active session **by IP alone**. If every caller through nginx
collapses to the same apparent address, that lookup stops meaning
anything — any caller reaching Drawbridge through nginx would match
whichever session happens to be active, regardless of which device it
actually is. Fixing this (`ProxyFix` trusting `X-Forwarded-For` from
nginx, the pod's only caller on that internal port) ships with this
release, verified by a new test, not deferred.

## Architecture

Pod `drawbridge` gains a 4th member, `drawbridge-nginx` (Alpine +
`nginx`/`nginx-mod-stream`, non-root), alongside the existing
`drawbridge`, `drawbridge-rsyslog`, and `drawbridge-bootstrap`.

Ports:
- **`8080`** (published, unchanged) — nginx's `stream` listener.
  `ssl_preread` decides per-connection: real TLS → the HTTPS server block
  (terminates TLS, `proxy_pass` to Gunicorn); anything else → a static
  "use https://" responder.
- **`8090`** (published, unchanged) — still `drawbridge-bootstrap`, serving
  the ZTP script. Untouched by this release.
- **`8078`** (internal only, not published) — Gunicorn's new bind,
  `127.0.0.1`-only, reachable only from nginx's HTTPS server block.
- One more internal-only loopback port for nginx's own plaintext
  responder.

`DRAWBRIDGE_PORT` only directly controls Gunicorn's bind when
`TLS_DISABLED` is set; otherwise Gunicorn always binds the fixed internal
`8078`, and `DRAWBRIDGE_PORT` is just the value nginx's conf and the pod's
`PublishPort=` have to agree on by hand if changed. `TLS_DISABLED` becomes
a documented, supported "bring your own reverse proxy" mode (operator sets
it and disables `drawbridge-nginx.service` themselves) rather than a
dev-only warning. Unlike an earlier draft of this design, disabling
`drawbridge-nginx` does **not** affect ZTP script serving — that's
`drawbridge-bootstrap`'s job, untouched and always running.

`drawbridge-rsyslog`'s `omhttp` actions move from `https://127.0.0.1:8080`
(with `allowunsignedcerts` to skip validation on that loopback hop) to
plain `http://127.0.0.1:8078` — Gunicorn's internal port has no TLS at all
now, so there's nothing to skip-verify anymore.

## File-by-file changes

- **New**: `container/nginx-drawbridge.conf` (stream + http blocks),
  `Containerfile.nginx`, `quadlet/drawbridge-nginx.container` (bind-mounts
  `data/tls` read-only — no `files/scripts` mount, that stays
  `drawbridge-bootstrap`'s alone).
- **Modified**: `drawbridge/gunicorn.conf.py` (internal bind, no TLS
  config when nginx is active), `drawbridge/main.py` (`ProxyFix`),
  `drawbridge/tls.py` (comment), `container/rsyslog-drawbridge.conf` and
  `quadlet/drawbridge-rsyslog.container` (plain HTTP to the new internal
  port), `quadlet/drawbridge.pod` and `quadlet/drawbridge.container`
  (port/comment updates), `Containerfile` (`EXPOSE` comment), `install.sh`/
  `uninstall.sh` and `.github/workflows/ci.yml` (add `drawbridge-nginx`
  image/build steps alongside the existing ones — nothing removed).
- **Tests**: new coverage asserting `ProxyFix` correctly rewrites
  `request.remote_addr` from `X-Forwarded-For`, and that a
  `provision-request`/`provision-complete` pair through a simulated proxy
  hop still pins/matches the real device IP.
- **Docs**: every place `docs/deployment.md`, `docs/architecture.md`,
  `docs/decisions.md`, and `docs/security-faq.md` described Gunicorn as
  the TLS terminator gets updated to describe nginx's role instead.
  `docs/kea.md`, `docs/api.md`, and the ZTP-script-serving parts of
  `docs/decisions.md`/`docs/security-faq.md` are **unaffected** —
  `drawbridge-bootstrap` didn't change.
